# 项目总览

## 1. 项目是什么

这个项目在做一套面向 Obsidian 的高考地理知识库导出系统。

它的目标不是单纯把试卷内容保存成 Markdown，而是把试卷、题目、答案、解析和知识点映射整理成一套可以长期维护、适合教学使用的知识结构。

项目当前服务三个核心目标：

1. 让使用者快速识别高频考点
2. 让教师能从知识主题直接回到对应题目、答案、解析和材料
3. 让新手教师、师范生能通过知识主题页快速熟悉当前高考考情

## 2. 当前核心思路

当前架构采用“聚合主题 + 单题详情 + 静态统计”的方式组织知识库。

### 2.1 为什么不再按细知识点建页

如果按 `level2` 大量建页，页面会非常碎，后续维护和阅读成本都很高。很多题虽然细知识点不同，但教学上仍然属于同一个核心主题，拆得太细反而不利于复习、串讲和统计。

所以现在改成按 `(module, level1)` 聚合出“知识主题页”，把 `level2` 保留为主题页内的细知识点标签和题目元数据，而不再单独生成页面。

### 2.2 为什么每道题单独建页

教师真正需要反复查看的是单题层面的完整信息，包括：

- 题干
- 材料
- 图片
- 答案
- 解析
- 来源试卷
- 关联知识主题

如果这些内容都堆在主题页或试卷页里，后续做备课、讲义、题目复用都会很累。把题目独立成页后，知识主题页可以保持简洁，单题页则成为稳定的“教学原子”。

### 2.3 为什么主入口要改成统计页

当题库规模扩大后，从试卷页逐份浏览效率很低。更合理的入口应该是：

- 先看哪些知识主题最常考
- 再进知识主题页看对应题组
- 再进单题页看完整答案与解析

所以首页当前主要连接到：

- 高频考点总览
- 试卷索引
- 知识主题总索引

## 3. 当前目录分层

### 3.1 源数据层

这一层保存原始资料和清洗后的结构化资料。

```text
raw_data/
convert_data/
clean_data/
```

其中最重要的是 `clean_data/questions/<试卷目录>/`，因为导出脚本当前主要从这里读取：

- 试卷 Markdown
- `questions.jsonl`
- `answers.jsonl`
- `explanations.jsonl`
- `question_knowledge_links.jsonl`

### 3.2 中间逻辑层

这一层是导出脚本本身。

```text
scripts/
  export_to_obsidian.py
  obsidian_export/
    io_utils.py
    source.py
    models.py
    transform.py
    render.py
    pipeline.py
```

### 3.3 展示产物层

这一层是导出的 Obsidian 知识库。

```text
obsidian_vault/
  00_首页.md
  01_试卷/
  02_知识主题/
  03_索引/
  04_题目/
  assets/
```

## 4. 当前页面体系

### 4.1 首页

首页负责做总导航，不承担全文承载任务。

### 4.2 试卷页

试卷页负责保留整套卷的原始语境，是从“整套卷”回看题目的入口。

### 4.3 知识主题页

知识主题页是当前知识库的核心页面类型。它既是考点分析页，也是专题卷母版页。

每个主题页当前会展示：

- 所属模块
- 题目总数
- 覆盖试卷数
- 涉及地区
- 涉及年份
- 下属细知识点
- 关联题目摘要

### 4.4 单题页

单题页是教学层面的最小完整单元。它承载完整内容，适合作为备课引用页、例题页和知识图谱节点页。

### 4.5 索引页

索引页当前包括：

- 高频考点总览
- 试卷索引
- 知识主题总索引
- 模块索引页

## 5. 数据模型设计

当前导出模型最重要的两个稳定键是：

- 题目稳定主键：`question_id`
- 知识主题稳定键：`(module, level1)`

这两类稳定键的作用是：

1. 避免页面命名和链接随着展示文案频繁变化
2. 为后续“精准更新”预留基础
3. 为主题合并、拆分和题目重映射提供可控的重建能力

## 6. 为什么要做脚本拆分

旧的单体脚本虽然能跑，但在这类项目里会越来越难维护，因为它把几个不同层次的问题混在了一起：

- 数据读取
- 模型组织
- 聚合统计
- Markdown 模板拼接
- 输出落盘

现在拆分后，每层职责更清楚：

- `source` 管输入
- `model` 管结构
- `transform` 管聚合
- `render` 管页面
- `pipeline` 管编排

后续要改页面样式，不需要冒险碰数据聚合逻辑；要改统计口径，也不必进入模板层做手术。

## 7. 当前项目最适合的使用方式

### 7.1 作为高频考点分析库

适合先看高频考点总览，再进入知识主题页分析题量、覆盖试卷数和具体题目。

### 7.2 作为教师备课知识库

适合从知识主题页进入单题页，查看完整材料、题干、答案和解析，直接用于备课参考。

### 7.3 作为新手教师学习地图

适合按主题聚合方式观察“当前高考常考哪些内容、常怎么设问、哪些题最能代表这个主题”。

## 8. 当前阶段的边界

当前版本已经能稳定导出知识库，但还没有把“教师知识库层”完全做满。

目前已经预留但尚未深化的内容包括：

- 教学备注
- 易错点
- 课堂提示
- 串讲线索
- 教材章节映射

这些内容的结构位置已经留好，后面更适合在单题页和知识主题页逐步扩展。

## 9. 后续建议路线

### 第一阶段

补齐单题页的教学标签字段，例如：

- 题型标签
- 能力要求
- 课堂用途
- 适用教学场景

### 第二阶段

增强知识主题页的教学分析能力，例如：

- 高频设问模式
- 常见误区
- 课堂串讲主线
- 典型案例

### 第三阶段

引入增量导出机制，让单题映射变化时只更新受影响主题页、统计页和单题页。

## 10. 开源分享建议

如果要把项目公开给更多人使用，建议把“可公开的代码”和“可能有版权或体积问题的数据产物”区分开来。

更适合开源的部分：

- 脚本
- 数据格式说明
- 页面结构设计
- 示例数据
- 文档

更适合本地保留或精简演示的部分：

- 原始试卷文件
- 大规模题目全文数据
- 本地 Obsidian 配置
- 全量导出的知识库

开源前建议结合 [开源发布清单](open-source-checklist.md) 做一次正式整理。
